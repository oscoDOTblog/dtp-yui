# CV2 Single-Job OpenClaw Flow

## Summary

Extend the existing lightweight `cv2/terminal-agent` flow from Gmail subject summarization to one selected job posting:

1. Start the visible OpenClaw `user` Chrome profile.
2. Open Gmail.
3. Find the newest email containing a job-related external link.
4. Open the job listing.
5. Extract the job title, company, location, description, requirements, and URL.
6. Score compatibility against the existing CV1 candidate profile.
7. Generate a tailored resume and cover letter as JSON and `.txt` files.
8. Open the application page but do not edit or submit it.
9. Print a terminal confirmation containing the job, score, recommendation, and generated document paths.
10. Save every state transition locally as JSON.

## Implementation Changes

### Terminal agent workflow

Update `cv2/terminal-agent/src/index.js` to use a single-job state machine:

- `starting`
- `gmail_opened`
- `job_email_found`
- `listing_opened`
- `job_extracted`
- `scored`
- `documents_generated`
- `application_ready`
- `completed` or `failed`

The Gmail phase will automatically choose the newest inbox message with a detectable external job link. It will not process multiple jobs.

OpenClaw remains the only browser automation layer. No Playwright, CDP, Next.js, Telegram, Docker, or background worker will be added.

### Job extraction

Use OpenClaw browser snapshots to inspect the selected email and linked job page.

Persist:

- Source Gmail message identifier when available
- Email subject and sender
- Listing URL
- Company
- Role title
- Location/work mode
- Salary when visible
- Description and requirements
- Extraction warnings for missing or uncertain values

If no usable link or job details can be found, save a failed/needs-input result rather than continuing.

### Compatibility scoring

Use Ollama with:

```text
OLLAMA_MODEL=qwen3:4b-instruct
```

The prompt will compare the extracted listing against the existing CV1 profile and evidence files under `cv2/seed`.

The model must return structured JSON containing:

- Compatibility score from 0–100
- Recommendation: `apply`, `review`, or `skip`
- Matching strengths
- Gaps or concerns
- Short reasoning
- Role-family classification

The prompt will explicitly prohibit invented experience or credentials.

### Document generation

Generate:

- Tailored resume content
- Cover letter content

Save both:

```text
cv2/generated-applications/<company>-<role>/resume.txt
cv2/generated-applications/<company>-<role>/cover-letter.txt
```

Also store the structured generated content and model metadata in `documents.json`.

The first version will not render PDFs or DOCX files.

### Application boundary

After document generation, OpenClaw will open the application URL in the visible browser.

It will not fill fields or submit anything in this version.

The terminal will print:

```text
Ready for review:
Company: Example Corp
Role: Software Engineer
Compatibility: 82%
Recommendation: apply

Resume: ...
Cover letter: ...

Type APPROVE to mark ready, SKIP to skip, or PAUSE to stop:
```

For this first version:

- `APPROVE` marks the job as approved/ready
- `SKIP` marks it skipped
- `PAUSE` leaves it resumable
- No option submits the application yet

## JSON Persistence

Each run continues using:

```text
cv2/runs/<run-id>/
```

The run writes after every meaningful state change:

- `run.json`
- `emails.json`
- `jobs.json`
- `applications.json`
- `documents.json`
- `events.jsonl`
- `gmail-snapshot.txt`
- `job-snapshot.txt`

Existing valid JSON records must be preserved if a later step fails. Writes should use temporary files followed by replacement so interrupted writes do not corrupt the last valid result.

## Testing

Verify:

- Visible OpenClaw Chrome starts with the `user` profile.
- The newest job-like Gmail message is selected automatically.
- A job link is extracted and opened.
- Listing fields are persisted.
- Ollama receives only the single listing plus candidate profile context.
- Compatibility JSON is saved.
- Resume and cover letter text files are generated.
- Application page opens without field edits.
- Terminal confirmation supports `APPROVE`, `SKIP`, and `PAUSE`.
- Interrupted runs retain their last completed state.
- Missing links, blocked pages, malformed model JSON, and missing job fields produce resumable errors.
- `node --check src/index.js` and `git diff --check` pass.

## Assumptions

- Gmail is already signed in through the OpenClaw `user` browser profile.
- The newest suitable email is the intended job.
- Job listings contain a directly accessible external URL.
- CV1 seed files remain the source of truth for candidate information.
- The first version prepares and reviews one application but does not fill or submit forms.
