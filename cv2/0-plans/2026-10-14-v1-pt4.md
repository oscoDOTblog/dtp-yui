# CV2 Isolated Job Verification Pipeline

## Summary

Refactor the terminal agent so every job is processed independently with a fresh, bounded context. The agent will process all listings found in the selected Gmail conversation, one at a time:

1. Open Gmail `Jobs` label.
2. Open the newest job email.
3. Extract all candidate listing links.
4. Process one listing in an isolated job context.
5. Open the listing.
6. Identify the company.
7. Open the company homepage or search for it.
8. Find the company careers page.
9. Verify the same role exists there.
10. Cancel and record the job if it does not exist.
11. Score only verified jobs.
12. Generate documents only for verified jobs.
13. Open the application page and ask for terminal confirmation.
14. Reset all in-memory job context before processing the next listing.

No Playwright, CDP, Next.js, Telegram, Docker, or background services will be added.

## Key Changes

### Context isolation

Replace the current single global job flow with a queue and per-job processor.

Each job receives:

- A stable local `jobId`
- Its own state object
- Its own compact browser snapshots
- Its own Ollama calls
- Its own persisted JSON updates
- A clean context reset after completion, cancellation, or failure

The process will never send the full Gmail email, full job page, candidate profile, and generated documents to Ollama together.

Each Ollama request will contain only the minimum required input:

- Extraction: compact listing text only
- Company verification: company/role/listing text only
- Scoring: normalized job fields plus compact candidate profile
- Resume generation: normalized job plus compact candidate evidence
- Cover letter generation: normalized job plus selected evidence/score

### Gmail and listing queue

The Gmail phase will:

- Open the `Jobs` label
- Open the newest conversation
- Extract all visible job links from the conversation
- Save the conversation snapshot locally
- Create one queued job record per detected listing
- Deduplicate links before processing

If the Gmail click response returns a Gmail URL, it will not be accepted as the listing URL. The agent will only accept:

- An external URL extracted from the email snapshot
- A URL returned by a successful OpenClaw navigation to an external page
- A listing URL explicitly identified by the browser snapshot

### Company and careers verification

For each listing:

- Open the job listing with OpenClaw.
- Extract compact facts: company, title, location, role keywords, and listing URL.
- Follow an explicit company link from the listing when available.
- If no company link is available, use OpenClaw browser search for the company name and careers page.
- Open the company careers page.
- Search the careers page for the same role using normalized title/company matching.
- Save the careers URL, search evidence, and verification result.

Verification statuses:

- `verified`: matching company careers listing found
- `not_found`: careers page found but matching role absent
- `uncertain`: company or role could not be reliably verified
- `blocked`: page, login, CAPTCHA, or browser issue prevented verification

Only `verified` jobs continue to scoring and document generation.

`not_found` jobs are marked:

```text
status: cancelled
cancelReason: careers_listing_not_found
```

They will not receive generated documents or an application approval prompt.

### Job state machine

Each job will use these states:

```text
queued
listing_opened
listing_extracted
company_found
careers_opened
careers_verified
cancelled
scored
documents_generated
application_ready
approved_ready
skipped
paused
failed
```

Every transition will immediately update:

- `jobs.json`
- `applications.json`
- `events.jsonl`
- `run.json`

### LLM context limits

Add explicit prompt budgets below the current 4,096-token model context:

- Listing extraction input: approximately 5,000–6,000 characters
- Careers verification input: approximately 4,000 characters
- Scoring input: approximately 6,000 characters
- Resume generation input: approximately 6,000 characters
- Cover-letter generation input: approximately 5,000 characters

Candidate data will be compacted before prompting:

- Candidate identity and preferences
- Relevant skills
- Relevant work history
- Relevant projects/evidence
- No full raw seed dump

If a snapshot is too large, the agent will save the full snapshot to disk but send only a compact extracted section to Ollama.

### Persistence and resume behavior

Run output remains under:

```text
cv2/runs/<run-id>/
```

Add per-job artifacts:

```text
jobs/<job-id>/
  listing-snapshot.txt
  company-snapshot.txt
  careers-snapshot.txt
  job.json
  score.json
  documents.json
```

Top-level files remain:

```text
run.json
emails.json
jobs.json
applications.json
documents.json
events.jsonl
```

If the process is interrupted:

- Completed jobs remain completed/cancelled.
- The current job remains in its last persisted state.
- A later run can skip completed jobs using the saved job URL and status.
- Valid JSON records are preserved through atomic temporary-file replacement.

### Terminal output

The terminal will show intermediate actions such as:

```text
[progress] Found 6 listing links in the Gmail conversation
[progress] Starting job 1/6: Software Engineer
[progress] Opening listing
[progress] Identified company: Example Corp
[progress] Opening company careers page
[progress] Searching careers page for matching role
[progress] Careers verification: VERIFIED
[progress] Scoring compatibility
[progress] Generating resume
[progress] Generating cover letter
[progress] Application page ready
```

For missing careers listings:

```text
[progress] Careers verification: NOT FOUND
[progress] Cancelling job: careers listing not found
```

For verified jobs, preserve the existing terminal review prompt. `APPROVE` only marks the job ready; it does not submit or edit forms.

## Tests and Acceptance Criteria

- Gmail `Jobs` label opens successfully.
- The top conversation is opened before link extraction.
- Multiple listing links are detected and deduplicated.
- Gmail conversation URLs are rejected as job listing URLs.
- Each listing gets an isolated job context.
- Full snapshots are saved locally but bounded prompt text is sent to Ollama.
- Company homepage and careers page are opened through OpenClaw.
- Matching role verification succeeds for a known listing.
- Missing role produces `cancelled` with `careers_listing_not_found`.
- Blocked or ambiguous careers pages produce `uncertain` or `blocked` without continuing automatically.
- Ollama requests remain under the `qwen3:4b-instruct` context limit.
- Resume and cover-letter generation occurs only after verification.
- Job state is persisted after every phase.
- Interrupted runs can be inspected and resumed.
- `APPROVE`, `SKIP`, and `PAUSE` continue to work.
- `node --check cv2/terminal-agent/src/index.js` passes.
- `git diff --check` passes.

## Assumptions

- The newest Gmail conversation is the source for all jobs in this run.
- Every detected listing is processed independently.
- An explicit company link is preferred; browser search is the fallback.
- A missing matching role on the company careers page cancels the job automatically.
- Uncertain or blocked verification does not proceed to scoring.
- The first version still opens application pages without editing or submitting them.
